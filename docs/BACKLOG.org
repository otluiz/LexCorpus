* Decisões recentes (contexto para quem chega)
  - MONOLITO MODULAR: 1 repositório, 1 imagem Docker, N containers/jobs.
    NÃO um container/imagem por banca. O que varia por banca é spider
    (código) e agenda (config), não artefato. Formalizar em ADR-0002.
  - PCI CONCURSOS: usar SÓ como índice de descoberta (quais concursos
    existem, qual banca, qual ano). Os PDFs vêm da fonte primária (site
    oficial da banca), como manda o contrato §1. Motivos: Turnstile
    (Cloudflare) protege as URLs reais de download e o robots.txt do PCI
    tem "Disallow: /*.pdf". Formalizar em ADR-0001.
  - FCC: os cadernos de prova NÃO são públicos (portal do candidato,
    acesso individual por hash de caderno). A fonte primária FCC entrega
    os GABARITOS oficiais (saem como editais públicos ao fim do certame).
    robots.txt da FCC bloqueia /concursos/ e *.pdf → crawls rodam com
    -s ROBOTSTXT_OBEY=False (decisão assumida, ver docstring do spider).
  - HEURÍSTICAS EM MÓDULO (ADR-0004, 07/08): a decisão é o módulo de
    funções puras lexcorpus/heuristics.py + base fina que só DELEGA
    (make_item + repasse dos hooks RE_*). base.py ALINHADA em 09/08:
    a duplicação foi eliminada e a classificação delega ao módulo;
    override por banca = sobrescrever o hook de classe (regime FORTE,
    igual ao parâmetro do módulo). Restam as cópias locais de
    fgv.py/fcc.py/pci.py (cebraspe.py é caso à parte: classifica por
    descricaoArquivo da API, não por heurística). Convergência no item
    "Migrar pci.py e fcc.py para heuristics.py".
  - DOCS: os .md migram para docs/; na raiz fica só o README.md.

** TODO [#B] Cadeia de técnicas de extração com fallback (LexCorpusSpider)
   Ideia (07/08): a base tenta MAIS DE UMA técnica de extração; se uma
   retorna zero itens, cai para a próxima. Subclasses declaram/ordenam
   as técnicas. Análise registrada em 07/08:
   - NÍVEL 1 (mesmo response, barato — fazer primeiro): técnicas são
     funções puras (response -> [candidatos]). Encadear na base é trivial
     porque dá para saber na hora se extraiu 0 itens:
     1. seletores CSS configurados (comportamento atual)
     2. varredura genérica de todo a[href$='.pdf'] da página
     3. JSON embutido (script[type='application/ld+json'], __NEXT_DATA__)
   - NÍVEL 2 (fallback ENTRE requests — adiar): tentar outro endpoint/
     página se o primeiro não rendeu exige saber o resultado só no fim
     da resposta; no Scrapy isso é agendamento preguiçoso + contador de
     sucesso. Complexidade real; implementar só quando um caso concreto
     aparecer (ex.: SPA sem JSON acessível).
   - Interface proposta: subclasses declaram `tecnicas = [método, ...]`;
     a base itera até a primeira não-vazia, sempre passando pelo gate
     final classificar_papel (evita falso positivo da técnica genérica)
   - Observabilidade: spider.stats.inc_value("tecnica/{nome}") — mede
     qual técnica resolve cada fonte e denuncia seletor quebrado
   - [ ] Implementar NÍVEL 1 na base + refatorar agregador_generico para
         declarar técnicas em vez de if/else
   - [ ] Cada técnica como função pequena testável (alimenta o CI)
